# 构造协议

> **定义 0.1（协议）**：协议是一组为了让系统继续跑下去而提前认下的约束，
> 其本质，是对于「以后会有人来改它」这件事的一次提前判断。
>
> 改动前先读。这不是风格建议，是这台机器能继续转下去的前提。

---

## 一、三条底层约定

1. **玩家只负责走位与瞄准，开火节奏是自动的。**
   玩家改的是系统，不是手速。任何需要 APM 的设计都不进这个作品。
   移动只认键盘，方向只认鼠标。节奏留给系统，方向留给玩家。

2. **一切随时间推进的量吃 dt**，dt 以 60fps 为 1。
   渲染与判定读同一份数据，不再各算各的。

3. **难度靠叠规则，不靠调数字。**
   数字只是让规则生效的手段。波相按波次开，击杀每跨一个数量级开一条阶跃、
   再跨一道换一把纪元的尺子。
   规则换了，原来的构筑可能就不成立——这才是难度的来源。

4. **规则要读得完。**
   同时生效的规则条数**必须封顶**。旧版的变异有十条，叠满之后没有任何一张表
   能说清场上正在发生什么——那不是难度，那是不可读。
   封顶之后的取舍交给玩家自己去做。

---

## 一·五、三条不属于「数值」的规则

有些东西看起来像数值，实际上是规则。它们不参与成长，也不被成长改掉。

| | 值 | 为什么不进 `MC.eff` |
|---|---|---|
| **判定点** | `HIT_R = 4.5` px | 它是「受击发生在哪里」的**定义**。养成能改它（`hitMul`），但它不能归零，也不上限表 |
| **受击冷却** | `HURT_CD = 60` 帧 | 它是「死亡读不读得出因果」的**前提**。养成全满也还是一秒 |
| **掉落基础率** | `0.11` | 它是「元件有多值钱」的**起点**。往下只被乘算抬，不被跳过 |

判定点与可见体积是**两个数**（`p.r` / `p.hitR`）。
把它们合一的直接后果是：所有减体积的元件都白做——画变小了，判定没变。

## 一·六、乘算的键不能从 0 起

这一条是这一版踩出来的，写在这里以免再踩一次。

`rateMul` / `dmgMul` / `radiusMul` / `hitMul` / `bossEvery` / `eliteChance` 这一类
键，语义是「相对中性值的偏移」或「基线」：

- **中性值一律是 1，不是 0。** `laws()` 把 `edge` 初始化成 0 再乘，
  结果永远是 0——收边那条律静默失效。
- **`compile` 里必须相乘，绝不能相加。** `0.82 + 0.82 = 1.64`：
  两个「收束」从「更小」翻成「更大」。
- **基线类的键要取极值，不做乘法。** 波相「盛」把 Boss 间隔**压到** 5 波，
  不是乘上去——`10 × 5 = 50` 会把 Boss 推得比不开还稀。

判断方法：问一句「两个都装上，是更好还是更差」。
`radiusMul` 相乘（两个收束=更小），`eliteChance` 取大（两个盛=更密），
`bossEvery` 取小（两个盛=更勤）。

## 二、单点收敛

所有数值钳制走 `MC.eff`，不在业务代码里写散落的 `if`。

```js
out.speed = MC.eff.eff('speed', out.speed);
out.hp    = MC.eff.eff('hpMax', out.hp);
```

`CAP` 是硬上限，`CALM` 是冷静模式的上限（只更低），`FLOOR` 是下限。
改上限 = 改 `core/eff.js` 里那张表，其它地方不动。

## 三、声明式表驱动

加内容 = 加表项。引擎、图鉴、装配台、培养皿、终端、内置说明自动认领。

| 表 | 位置 | 加一项的效果 |
|---|---|---|
| `BASES` | `world/modules.js` | 多一个元件基型（等级由程序展开成 Ⅰ/Ⅱ/Ⅲ） |
| `SYNERGY` | `world/modules.js` | 多一条环形协同（按基型匹配，与等级无关） |
| `ENEMIES` | `world/enemies.js` | 多一种敌人 |
| `PHASES` / `ELITES` / `BOSSES` | `world/waves.js` | 多一条波相 / 一种精化徽记 / 一个 Boss |
| `LADDER` | `world/ladder.js` | 多一级阶跃 |
| `EPOCHS` | `world/epoch.js` | 多一把纪元的尺子（改的是数字怎么长） |
| `NAMED` | `world/reactions.js` | 多一条「有名堂」的反应（其余自动推导） |
| `NODES` | `world/nursery.js` | 多一个局外养成节点 |
| `WEAVE` / `EVENTS` | `world/anomaly.js` | 多一缕整局织构 / 多一条当波事件 |
| `SKINS` / `STYLES` | `core/cosmetics.js` | 多一套皮肤 / 多一种游戏风格 |
| `ROOMS` | `index.html` | 多一个房间 |

**硬要求**：新增一张表，就要在 `guide/guide.js` 里加一页或一节。
内置说明的测试会逐项点名「全部可玩内容都展示到了」——
漏了的话，玩家会在游戏里碰到一个没写在任何地方的东西。

## 三·五、局内与局外

`core/bus.js` 的 `blank()` 里每一项都标了 `[局外]` 或未标（局内）。

- **局内**：波次、本局击杀、生命、护壁、蓄能、织构、**未装配的元件**。
  `Engine.reset()` 与 `onDead` 都清这些。
- **局外**：已点亮的图鉴、装在环上的装配、养成、残渣、纪元、累计击杀、阶跃。
  只有 `MC.bus.wipeMeta()` 会清。

**这一版改了一条**：`inventory` 从 `[局外]` 变成**局内**。
理由：合成改成瞬时之后，元件就成了这一局的素材。
素材留在局外，「捡到什么」就只是一个收集动作；素材留在局内，
它才是一个决定——「这两个我要合，还是留着」。

配套地，库存的语义从「总数」改成「**未装配数**」：
装上槽位扣一个，卸下来还一个。三个唯一写入口在 `core/bus.js`：
`invAdd` / `invTake` / `invClearRun`。别在别处直接改 `state.inventory`。

旧存档的迁移在 `migrate()` 里：把 rig 上占着的那些从 inventory 里扣掉。
一次性的，`__invMigrated` 标记。

两个入口都要显式存在：**重置本局**只动左边，**硬重置**动右边，
编号与偏好（冷静 / 声轨 / 皮肤 / 风格）两边都不动——那是人的偏好，不是存档。

养成室（`world/nursery.js`）是唯一的局外货币出口：每局倒下时按本局表现结算残渣，
买下的节点永久生效，其中一部分按**真实时间**孵化。

## 四、状态同步：bus 的三条铁律

1. **`load()` / `reset()` 只写字段，绝不替换 `state` 对象本身。**
   替换对象的后果是：其它模块手里握着的还是旧引用，改了不生效，而且极难查。
   这个 bug 在上一个项目里犯过一次。

2. 房间只发「改了什么」，由总台决定要不要让引擎重新编译构筑。
   房间不直接碰引擎。

3. 三通道联动：BroadcastChannel → postMessage → 聚焦重读。
   逐级降级，任何一个通了就算通。

## 五、随机

**定义 5.1（随机）**：随机不是把数字搅乱，随机是同一份规则每一局落在不同的位置上。
即：可复现是随机的前提，不是它的对立面。

播种用 `mulberry32`，字符串转种子用 FNV-1a。
每次操作派生独立种子（`rngFrom(seed, tag)`），不共用一条流——
否则改了敌人数量，地形也跟着变。

同种子 + 同波次 = 同一张时刻表。这是可复现的前提。

### 五·一、引擎里的三条流

| 流 | 谁用 | 什么时候重播 |
|---|---|---|
| `rrng` | 判定（暴击、掉落、再生、镜像） | 每次 `reset()` |
| `_vrng` | 视觉（震屏偏移） | 每次 `reset()` |
| `e.rng` | 敌人 AI 自己的抖动 | 生成时 |

三条流分开的理由：暂停时只 `draw` 不 `step`，
若视觉去吃判定那条流，同一局的判定序列就会因为暂停次数不同而分岔。

### 五·二、三张随机表（`world/anomaly.js`）

| 表 | 抽的时机 | 管多久 |
|---|---|---|
| `WEAVE` | 开局抽两缕 | 整局 |
| `EVENTS` | 每波抽一条 | 这一波 |

**织构、事件与波相的合流点只有一个**：`Engine.prototype.recalcRule()`。
织构（整局）叠上当波事件（一波）叠波相（按波次开）叠风格（一组乘算），
算出 `this.rule`，引擎各处只读 `this.rule`。
散落的 `if (weave.id === 'xxx')` 是把规则写死的开始，一律不写。

风格「静」把当波事件整条按掉——它写在 `waveEvent()` 调用之前，
所以事件表不用知道自己有风格这回事。

**波相取代了旧的变异**。理由不是「变异太难」，是**规则多到读不完**：
十条永久变异叠满之后，没有任何一张表能说清场上正在发生什么。
现在 `PHASES` 一共 5 条，条数封顶，全部摊在总台上。

**精化取代了旧的变体**。理由是**看得见才可以针对**：
旧变体是看不见的百分比堆叠，你只知道「这一只不太一样」。
现在外圈加一个字，掉双份，死了还炸或者还分——徽记即说明。

### 五·三、两条新的进度轴

阶跃与纪元读的是**同一个数**（累计击杀），改的是**不同的东西**：

| | 改的是 | 表 |
|---|---|---|
| **阶跃** | 场上会发生什么 | `world/ladder.js` |
| **纪元** | 数字本身怎么长 | `world/epoch.js` |

七个律键全是乘算，中性值 1。养成室的「律」分支能改门槛、坡度与 Boss 系数，
所以纪元不是纯线性地越来越难——它是**可以被改写的**。

### 五·四、删层的边界

自动机那一层已经整层删掉。它留下来的一条教训值得写进协议：

**一个系统如果只能靠「另一张表」来解释自己，它多半不该存在。**
自动机要玩家先读两张表（程序表 + 触发器表）才知道这一波发生了什么，
而它做的事又全部可以由玩家在装配台与养成室里手动完成——
它提供的不是新的决定，只是把已有的决定提前做了。于是它整层删掉：
`core/automata.js`、序室、终端、养成室的「序」分支，一次清干净，不留空壳。

删层的检查清单：删文件 → 删脚本引用 → 删声明表项 → 删养成/图鉴里的读数 →
删说明与 README 的章节 → 删测试断言。**最后一步最容易被跳过**，
而跳过的后果就是「测试全绿但页面上有个房间打不开」。

## 六、终止守卫

任何循环必须有出口。波次调度、连锁、分裂、吞噬，全部有计数上限或帧上限。
无上限的递归/循环不进代码。

---

## 七、无障碍

- 对比度 WCAG AA。
- 不做周期闪烁、全屏反相、突然强光。
- 受击只做一次短闪。
- 冷静模式是永久开关，不是提示。
- **画面特效**与**显示敌方血条**是两个独立开关，都在设置页里，都不进判定。
- **皮肤只改颜色**：`core/cosmetics.js` 的 `SKINS` 表里不许出现任何参与判定的字段。
  写了就是 bug——那张表会被 `applySkin()` 整个铺到 CSS 变量上，
  多一个键就多一处「看起来像设置、其实是规则」的东西。

---

## 八、文案

页面上的文案一律进 `core/lexicon.js`，不散着写。

**一句话写完，不解释第二句。** 解释性文案是这个作品的反面——
系统的乐趣在于自己看出来，不在于被告诉。

语气守卫（`npm run test:tone`）扫的是**渲染后的正文**和所有声明式表，不是源码。
它拦的是「一味否定、漠不关心」那一类调子。

---

## 九、诚实披露

- 声轨默认静音、手势门控、不进判定、不写进卷宗。
- 冷静模式只钳上限。
- 已知限制写在 README 和终端的卷宗导出里，不藏。

## 十、难度校准的方法

改任何数值前先跑无头探针：把 `world/*.js` 装进 Node `vm` 沙箱
（**不要**用 jsdom，慢两个数量级，会超时），配一个势场导航的脚本玩家，
跑几套构筑对比「死在第几波 / 多少击杀」。

判据：
- 裸奔与正经构筑的击杀差 **≥ 10 倍**，否则机制等于零。
- 只堆同一种元件 **打不过** 凑协同。
- 最强的构筑也要死，只是死得晚（当前：第 74 波）。
- 阶跃门槛要可走到：第一阶 ≤ 1000 杀，最后一阶 ≤ 1e6。

校准记录：
- 敌人血量从线性 `1+0.19w` 改成二次 `1+0.19w+0.012w²`，差距从 2.5 倍拉到 70 倍。
- 加入养成室后差距回到约 5 倍——局外成长本来就会压缩相对差距，这是预期的；
  真正的分化体现在**波次**上（15 → 74）。
- 元件掉率从 0.6 压到 0.11，并加入等级门槛（二级第 6 波、三级第 14 波起）。

## 十一、不写负面态度的文案

「不公开，你自己试」「不告诉你它叫什么」这一类句子一律不写。
它们读起来像是在拒绝，而不是在邀请。

同一件事的正向写法：
- 「协同表不公开，你自己试」→「挨着的两个如果对得上，会自己长出第三样东西」
- 「不告诉你它叫什么」→「见过的才在这里占位，没见过的留一个空位」
- 「没有这条指令」→「这条不在册子上」

语气守卫（`npm run test:tone`）扫**渲染后的正文**与所有声明式表，
拦的是「没有 / 无法 / 不能 / 不可能 / 不必」这一组字面否定词。

## 十二、敌人不解释自己

敌人名字用晦僻字（灰针、卯、孖、霣、湮、玺……），注释里不写它干什么。
它是什么，由玩家自己在场上撞出来。图鉴里只留一个字形，不留说明。

「多到把人吓疯，可从字面上看不出它们是什么」——数量与沉默一起起作用。

**精化**（`ELITES`）也不这么写。它给的是外圈加一个字——不是三角形框加一个无名记号。
理由很直接：**看得见才可以针对**。
旧版的变体在敌人外面套一个三角形框，不告诉你套的是什么，
于是玩家只知道「这一只不太一样」，猜不出差别，也就谈不上针对。
精化把七种徽记都写在明面上（疾 / 厚 / 巨 / 微 / 壳 / 孖 / 灼），
猜的环节被取消了，但针对性还在。

「隐藏机制优先于显式教程」这条主张的前提是：**机制存在，只是不主动说**。
判别标准是「你能不能据此做出不同的选择」——
看不见的百分比堆叠做不到这一点，所以它不是隐藏，是噪音。

## 十三、内置说明也是声明式的

**定义 13.1（文档）**：文档是同一份声明表的第二种读法，其本质，是对于「数据只有一份」这件事的一次确认。

`guide/` 不存数据。它把 `world/*.js` 与 `core/*.js` 的表直接渲染出来：

- 加一个页面 = 在 `guide/guide.js` 的 `PAGES` 里加一项，导航、路由、搜索索引自动认领。
- 表的条数、数值、注脚全部当场读，所以表改了它就改，**不存在第二份需要同步的数据**。
- 搜索扫的是**渲染后的正文**（不是源码），所以新增内容不改一行搜索代码就能被搜到。
- 所有数字格式化走 `fmt()`，所有块渲染走 `card()/row()/def()`。
  别在各处各拼一段 HTML——那会让改版变成考古。

**改名的理由**：它原本叫 `wiki`，而这个词把「读文档」和「查外部资料」混在一起。
它其实是**游戏内的一份东西**——跟游戏读同一批表、走同一套数值。
所以它叫「内置说明」，住在 `guide/`，从总台底部可以直接点进去。

### 十三·一、这一版新增的硬要求

**可玩内容必须展示得出来。** 新增一张表，就要在 `guide/guide.js` 里加一页或一节。

这不是文档洁癖：内置说明的测试里有一段逐项点名的断言
（`全部可玩内容都展示到了`），点名 21 个词，涵盖合成、判定点、受击、瞄准、
波相、精化、自动机、纪元、律、皮肤、风格、元件、协同、敌人、阶跃、养成、反应、Boss。
少一个词就是一条失败。

漏了的话，玩家会在游戏里碰到一个没写在任何地方的东西——
而「隐藏机制优先于显式教程」这条主张的前提是：**机制存在，只是不主动说**，
而不是**机制根本不存在于任何可查的地方**。

如果哪天内置说明上出现了一个源码里没有的数字，那是 bug，数字应该回到声明表去。

## 十四、勘误

本文按追加式勘误维护：发现定义漏了一层，就在末尾追加一条 `注 N`，
**不回头改编号，也不回头改原定义**。编号跳号、重复、与正文不一致，都是预期内的。

- **注 1（概念增加 1）**：§五 的原定义只说了「随机是可复现的」。
  漏的一层是：随机同时是对于「抽法」与「抽到什么」的区分——
  抽法是规则，抽到什么是结果。本作两张随机表改的是抽法，不是结果。
- **注 2（概念增加 2）**：§三 的表里 `WEAVE` 与 `EVENTS` 都标了「多一项」，
  但两者入口不同：织构在 `reset()` 抽，事件在 `startWave()` 抽。
  加表项时不用管入口，改入口时得同时看这两处。
- **注 3（原定义修正声明，不改编号）**：§二 说「所有数值钳制走 `MC.eff`」。
  织构、事件与波相的钳制不在这里，在 `recalcRule()` 里——
  因为那三张表的键是动态的，`eff` 的三张静态表管不到。
  判定点与受击冷却更进一步：它们连 `recalcRule()` 都不进，因为它们不是钳制项。
